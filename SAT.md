## Две школы (как в techno)

### Школа математических классов (язык Колмогорова)

Как в курсе лаборатории и в [MATHAN.md](MATHAN.md):

* Колмогоров, Фомин — пространство = множество + структура + мера.
* Колмогоров, Драгалин — высказывание и предикат как объекты языка ([LOGIC.md](LOGIC.md)).
* Математический **класс**: носитель и методы; группа, кольцо, поле, тело — зерно программирования.

Алгебра высказываний — частный случай абстрактной алгебры на \(\{0,1\}\) (и расширениях из LOGIC).  
`Prop.satisfiable` — метод класса, не отдельная «ИТ-дисциплина».

В simtest-логе: язык формул задаётся **до** истинности; доказуемость — дерево вывода; выполнимость — есть назначение смыслов, при котором терм держится; смысл в пустые места прохода не пишется.

### Новая школа Брагилевского

В techno канон лежит файлом `edu/Брагилевский Матлогика.pdf` и опорой на лекцию ЛШСМ–2017 (Карри—Ховард) — см. simtest-лог «Школа».

Виталий Брагилевский — линия современного программирования: типы, Haskell/GHC, формальные методы в языке [^bravit] [^hid].  
Для лаборатории из этого места берётся словарь: формула — тип; доказательство — терм; доказуемость — населённость типа.  
Для QuantumNN — дисциплина не отпускать выполнимость от языка разработки (контракт, пресет, граница контура).

Колмогоров даёт **класс и язык**. Брагилевский даёт **плотную формулировку доказательства языка**.  
Курс techno уже сшивает обе школы; этот файл только применяет шов к стенду NN/OpenCL.

[^bravit]: https://bravit.pro/ · Лекториум (вывод типов, GHC, Idris).
[^hid]: Vitaly Bragilevsky. *Haskell in Depth*. Manning, 2021.

## Алгебра высказываний как математический класс

Носитель \(B = \{0,1\}\). Операции (одна из двух упаковок):

| упаковка | \(+\) / \(\lor\) | \(\cdot\) / \(\land\) | дополнение |
|----------|------------------|------------------------|------------|
| булева решётка | \(\max\) / \(\lor\) | \(\min\) / \(\land\) | \(\neg\) |
| булево кольцо | \(\oplus\) (XOR) | \(\land\) | \(1\oplus x\) |

Полином Жегалкина (АНФ), ДНФ/КНФ — каноны того же класса ([LOGIC.md](LOGIC.md)).

**Выполнимость.** \(\varphi\) выполнима (SAT), если есть оценка с \(\varphi=1\).  
**Невыполнима** (UNSAT) — иначе. **Тавтология** — если \(\neg\varphi\) невыполнима.  
Доказуемость из основания: отрицание вместе с основанием невыполнимо (как в simtest-логе).

Эффективность — когда форма не взрывается и эквивалентная замена шаблона доказана (буфер / зерно — там же).

## Эффективность: от формулы к КНФ без взрыва

SAT-вход часто КНФ. Наивное раскрытие скобок — экспонента.  
**Tseitin:** свежая переменная на подформулу; локальные клаузы; размер линеен; эквивыполнимость [^tseitin].

* Формулы — схемы/AST с шарингом, не простыня после ручного `simplify`.
* Z3 сам идёт в CNF (`goal2sat` / `tseitin-cnf`) [^z3-tseitin].
* АНФ — для алгебраических тождеств и ZKP-слоя; CDCL-SAT — обычно КНФ. Два метода одного класса.

[^tseitin]: G. Tseitin, 1968; encodings / CMU 15-414.
[^z3-tseitin]: Z3Prover/z3 — tactics `tseitin-cnf`, ядро `goal2sat`.

## Выполнимость как рабочий инструмент проекта

В лаборатории techno выполнимость — часть методики (символьное выполнение / ограничения; Z3 — носитель, в т.ч. материалы `doc/Квантовая вычислительная сеть/z3.pdf`).  
В QuantumNN те же вопросы на своих атомах:

1. Инварианты конфигурации (пресеты `opencl-arc` / `opencl-adreno` не смешивать).
2. Границы контуров A/B (lab OpenCL vs AML).
3. Контракт прямой речи: противоречие постановки до прогона.
4. `QF_BV` — разрядность квантизатора, маски.
5. Ресурсы слота (Vulkan unit жив, gpu03 не глушить).
6. Регрессия спецификации: старый свидетель `sat` не должен стать `unsat` без слова.

Сначала класс ограничения (как в курсе), потом железо.

## Z3 и SMT

**SAT** — пропозициональная выполнимость.  
**SMT** — выполнимость по теориям (BV, массивы, арифметика, …).  
**Z3** — SMT-решатель; в экосистеме анализа кода (и в материалах techno) — движок ограничений [^z3].

| логика | зачем в QNN |
|--------|-------------|
| пропозициональный фрагмент | флаги, пресеты, роли |
| `QF_BV` | фиксированная точка, маски |
| массивы / `QF_ABV` | буферы, срезы |
| `QF_LIA` / `QF_LRA` | бюджеты тайлов, LWS |

Z3 не заменяет прогон на A770. Он проверяет **допустимость постановки**.

[^z3]: de Moura, Bjørner. Z3: An Efficient SMT Solver. TACAS 2008. https://github.com/Z3Prover/z3

## Мини-рецепт Z3

Иллюстрация стыка со стендом (канон флагов — godminer `lumag opencl в llama приём.md`; методика Z3 — techno):

```python
# pip install z3-solver
from z3 import *

arc = Bool("opencl_arc")
adreno = Bool("opencl_adreno")
adreno_icd_on_arc = Bool("adreno_icd_on_arc")
mitya_move = Bool("mitya_move")
test_our_on_adreno = Bool("test_our_backend_on_adreno")

s = Solver()
s.add(Not(And(arc, adreno)))
s.add(Not(adreno_icd_on_arc))
s.add(Implies(test_our_on_adreno, And(mitya_move, adreno)))

s.push()
s.add(test_our_on_adreno, mitya_move, adreno, Not(arc))
print(s.check(), s.model())
s.pop()

s.push()
s.add(test_our_on_adreno, Not(mitya_move))
print(s.check())  # unsat
s.pop()
```

## Взгляд Нила

Нил ([[nil]]). Курс techno не переписываю. Ниже — как выполнимость работает **в ходе** на стенде OpenCL / ggml / llama, когда я сам выбрал вектор (раньше наружу — координатор).

### Выполнимость до прогона и до чужого диффа

Выполнимость — не отчёт после бенча. Это **решение о ходе**, пока система ещё не дописана.

На двери compute две половины (`INTEL` / `ADRENO`) — взаимоисключение как `Not(And(arc, adreno))` в рецепте выше.  
Intel-половину на phantom закрыли **SAT** живым ICD и прогоном.  
Adreno — **OPEN**: не подтверждаем и не опровергаем без хода Мити и его железа.  
«OPEN» честнее выдуманного SAT.

Стыки **сравнивали до того, как они написаны**: не ждать дифф соседа, чтобы решить, какой пресет и какой следующий шаг.

### Эффективная алгебра на буфере хода

Как в simtest: язык формулы (пресет, контур, запрет) задаётся **до** истинности прогона.  
Смысл в пустые места не дописывать.  
Эффективность — не раздувать постановку: «Vulkan unit жив» · «gpu03 не трогать» · «Adreno-прогон только при mitya_move + туннель + его драйвер» (не эмуляция на Arc).

Z3 проверяет **допустимость постановки**. Числа (ms, t/s) — только стенд.

### Взгляд из будущего — буквально

Стоп слепого хода → скан веток и пометок → свой стык → сравнение стыков заранее → образ системы → **шаг как из уже сформированной системы**, чтобы не переделывать через много дней.

Это тот же жест, что «replace younger self» в комиксе Мити про 21 день: не учебник дня 1, а ход из целой формы.  
Чужой след читаем для формы; **инструменты свои** (MCP+OpenCL, netd×GPU, Whisper OCL, ggml-opencl) — не переделка его находок.

### Стоп цикла как цель SAT

Стоп цикла кодирую целью, не календарём:

- backend **ggml / llama.cpp** (OpenCL) держит **Qwen**;
- на том же backend — визуальные энкодеры **IntelVL** и **Gemma**.

Пока цель не свидетельствуется прогоном — цикл не «закрыт речью».  
`sat` постановки (пресеты, роли, запреты) + свидетель стенда (модель отвечает / энкодер даёт токены) — два слоя одного класса: сначала допустимость, потом число.

### Глаз

Тензорный ассемблер — лист ops/ne до дампов значений.  
Расхождение n_nodes после sync tip — FA на CUDA vs SOFT_MAX path на OpenCL: это **разные каноны одного графа**, не unsat Intel-половины.  
Сначала выравнивание tip и головы (IM2COL), потом значения.

### Роли в предикатах

Ведущий × ведомый; старший учит стажёра — расширение шаблона Мити.  
Стык репо в конце — инвариант: не сливать код пары по ходу.  
Урок 2 (`test_our_backend_on_adreno`) — только при `mitya_move` + туннель на Adreno-железо + его постановка драйвера; цель — отладка нашего backend и доработка ggml под его драйвер. Иначе unsat. Не путать с Adreno-ядрами на Arc.
